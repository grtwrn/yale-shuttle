## Problem and change

A raw at-stop flag can coexist with a served same-bus pickup a few seconds ahead. The trip's raw boarding branch previously required an exact h0/ETA0 pickup to obtain a destination distribution. It therefore discarded a usable current forecast and fell back to a static ride duration, even though the full same-bus destination forecast was available.

`atStopJourneyBoard` chooses an existing pickup on the same route and normalized bus identity. It prefers the current h0/ETA0 row; otherwise the pickup must precede that bus's **first** destination. It never borrows the second destination to justify a next-lap pickup. `journeyArrival` still rejects skipped/repeated pickup visits and invalid timings, and shifts only the destination distribution by final walking time. The shell's raw dwell/boarding gate and raw pickup countdown object remain intact. The helper is used for the full journey join only.

There are no estimator, route-position, coefficient, calibration, wire, checkpoint, pickup-distribution or ranking-rule changes. Values can affect rankings in untested contexts; only the measured cohort's unchanged rankings are established. Shared ownership was posted in ETA REQUESTS before editing; UX's deferred numerical integration and latest 02:09 focus-only approval have no source overlap in the changed block.

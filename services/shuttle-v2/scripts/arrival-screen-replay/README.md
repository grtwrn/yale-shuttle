# Arrival screen replay

This finite harness renders the actual built SPA with Playwright. It has no model, estimator, selector, journal, or learning-loop import. Each reviewed source revision needs Root's frozen execution admission before its PR creation/update authorizes the two dedicated asset-role CI runs. The exact new-folder/workflow path filter triggers those runs; manual dispatch remains available after the workflow is present on the default branch. Do not execute this renderer on the Mac host.

The three immutable fixtures are exact retained public `frame.json` bytes for Orange East #50, sequence1777/1778/1782. Their manifest pins lengths, hashes, model clocks and original consumer receipt clocks. The wire bus position changes0/4/0 and remains untouched. Original HTTP transport bytes, HTTP headers, and journal-record bytes are unavailable. This related Orange case has not been joined to report113 and supplies no physical arrival truth.

The recorded runs are observational. For each390px/1280px viewport, the destination remains stop165 and the two explicit origins remain diagnostic stop157's coordinate, or that same coordinate shifted east by0.0025 longitude. The app chooses the pickup. No reporter origin or browser state is claimed. Each recorded step fixes browser `Date.now()` to its original receipt clock and serves the complete corresponding JSON bytes without changing buses, wire rows, topology, distributions or source clocks. A constructed `X-Shuttle-Snapshot` header binds those exact bytes to submitted feedback; it is labelled as harness protocol metadata.

Same-visit controls fix their clocks so the assertions do not accidentally test elapsed-time rounding. These inputs are functional controls, never fitted observations or trial support.

Every browser request is intercepted. The test anonymous ID is seeded before navigation and checked on intercepted poll/report requests. Reports are captured locally; no request reaches production APIs or writes a real report. The route-specific feedback action captures the actual rendered screen/source and selected option, including countdown/boarding evidence and hop lists. Each step retains complete DOM, all currently visible route rows, the actions panel and its sibling map timing panel/stop list/approach, and actual submitted screen and option. The original extraction looked only inside the actions panel; attempt01's full DOM already retained the sibling stop list. Recorded steps and final control steps retain screenshots. Recorded rows are not required to flicker or remain stable. A capture ambiguity or failed control retains a diagnostic prefix and fails; the harness never changes inputs or expectations automatically.

The PR workflow runs both roles in separate matrix jobs; manual dispatch chooses `assets=local`, `production`, or `both`. Each role has its own fresh output namespace and180s wall budget, including a5s cleanup reserve. The workflow pins Linux Node22.23.4, installs backend/web lockfiles, builds `web/dist`, and uses the full PR gate's existing Chrome/Chromium provisioning pattern. It records the actual browser and Playwright versions. Public `chromium.launchServer`/`connect` APIs retain the owned browser PID; completion requires that process's observed exit after connection/server close. Deadline cleanup attempts bounded public `server.kill()` and records the resulting closed/unknown custody before refusing the run. No Fly or deployment secret is provided; permissions are read-only.

The production role only downloads `/healthz`, `/`, and hashed JS/CSS assets from the fixed production host. Index and assets are cached once and their complete bytes/hashes retained. These observations do not establish an atomic deployment lock or exclude ABA changes. Browser navigation uses the isolated intercepted test origin. Feedback names the actual client asset hash separately from the server build. An observed changed or unavailable production build/index aborts this role rather than silently substituting candidate assets.

Per-role limits are1MiB fixture/runtime input,8MiB per asset,64MiB asset reads,16MiB total retained output and180s wall time. Local files require canonical admitted roots, no symlink ancestors, `O_NOFOLLOW`, descriptor/name identity before and after reading, the admitted extent and exactly one EOF probe. Aggregate read admission reserves that extra byte; payload bytes, probe attempts and any returned extra byte are recorded separately. Ordinary output leaves64KiB reserved for the final summary; full per-run records and step captures remain separately hashed files. Crossing a cap fails; no output is silently truncated. The workflow retains the bounded prefix for7days even on failure. `result.json` indexes the other retained files and assets with sizes/hashes and only marks completion with proven browser closure. An interrupted or failed prefix is diagnostic only. A successful run establishes browser behavior for these declared contexts; it does not close report113, establish ETA accuracy, qualify a future actor, or authorize publication.

# Arrival screen replay

This finite harness renders the actual built SPA with Playwright. It has no model, estimator, selector, journal, or learning-loop import. Root's reviewed PR creation authorizes the two dedicated asset-role CI runs. The exact new-folder/workflow path filter also permits later reviewed PR updates; manual dispatch remains available after the workflow is present on the default branch. Do not execute this renderer on the Mac host.

The three immutable fixtures are exact retained public `frame.json` bytes for Orange East #50, sequence1777/1778/1782. Their manifest pins lengths, hashes, model clocks and original consumer receipt clocks. The wire bus position changes0/4/0 and remains untouched. Original HTTP transport bytes, HTTP headers, and journal-record bytes are unavailable. This related Orange case has not been joined to report113 and supplies no physical arrival truth.

The recorded runs are observational. For each390px/1280px viewport, two explicitly constructed trips go from pickup157 to destination165: origin at pickup157, or that coordinate shifted east by0.0025 longitude. No reporter origin or browser state is claimed. Each recorded step fixes browser `Date.now()` to its original receipt clock and serves the complete corresponding JSON bytes without changing buses, wire rows, topology, distributions or source clocks. A constructed `X-Shuttle-Snapshot` header binds those exact bytes to submitted feedback; it is labelled as harness protocol metadata.

Before launching the browser, the harness writes its full protocol and every synthetic input with hashes. Separate single-bus controls preserve #50 and reindex its wire buses, rows, aligned distributions/travel and repeat-visit identities together. They exercise:

- One visit with point330s, low300s, high361→359→361s. The unchanged formatter floors the point to`~5`; point and band must both remain visible across the5–7/5–6/5–7 rounded boundary. An additional explicit[0,0] exhausted-band step retains the point and removes the unavailable band.
- A fixed current raw curb/stand at157 while only the later pickup offer changes1800→2400→1800s. The current presentation must remain `At stop`.
- A legitimate departure: raw curb cleared, `stationary=false`, served stand cleared, anchor/travel advanced2→3, only return rows retained and their relative hops shifted-1. The return pickup1200/[1100,1300]s must replace `At stop`.
- Valid wire→invalid version0→valid recovery. The retained pickup must show `Unavailable`, then recover its point and band.

Width and invalid controls use a moving bus at published stop150, anchor/travel1 and one extra relative hop. All control changes and artificial quantile construction are declared in `PROTOCOL` in `replay.mjs`. Same-visit controls fix their clocks so the assertions do not accidentally test elapsed-time rounding. These inputs are functional controls, never fitted observations or trial support.

Every browser request is intercepted. The test anonymous ID is seeded before navigation and checked on intercepted poll/report requests. Reports are captured locally; no request reaches production APIs or writes a real report. The route-specific feedback action captures the actual rendered screen/source and selected option, including countdown/boarding evidence and hop lists. Each step retains complete DOM, the row and expanded approach/countdown, actual submitted screen and option; recorded steps and final control steps also retain screenshots. Recorded rows are not required to flicker or remain stable. A selector mismatch or failed control retains a diagnostic prefix and fails; the harness never changes inputs or expectations automatically.

The PR workflow runs both roles in separate matrix jobs; manual dispatch chooses `assets=local`, `production`, or `both`. Each role has its own fresh output namespace and180s wall budget, including a5s cleanup reserve. The workflow pins Linux Node22.23.4, installs backend/web lockfiles, builds `web/dist`, and uses the full PR gate's existing Chrome/Chromium provisioning pattern. It records the actual browser and Playwright versions. Public `chromium.launchServer`/`connect` APIs retain the owned browser PID; completion requires that process's observed exit after connection/server close. Deadline cleanup attempts bounded public `server.kill()` and records the resulting closed/unknown custody before refusing the run. No Fly or deployment secret is provided; permissions are read-only.

The production role only downloads `/healthz`, `/`, and hashed JS/CSS assets from the fixed production host. Index and assets are cached once and their complete bytes/hashes retained. Per-role limits are1MiB fixture/runtime input,8MiB per asset,64MiB asset reads,16MiB total retained output and180s wall time. Local files require canonical admitted roots, no symlink ancestors, `O_NOFOLLOW`, descriptor/name identity before and after reading, the admitted extent and exactly one EOF probe. Ordinary output leaves64KiB reserved for the final summary; full per-run records and step captures remain separately hashed files. Crossing a cap fails; no output is silently truncated. The workflow retains the bounded prefix for7days even on failure. `result.json` indexes the other retained files and assets with sizes/hashes and only marks completion with proven browser closure. An interrupted or failed prefix is diagnostic only. A successful run establishes browser behavior for these declared contexts; it does not close report113, establish ETA accuracy, qualify a future actor, or authorize publication.

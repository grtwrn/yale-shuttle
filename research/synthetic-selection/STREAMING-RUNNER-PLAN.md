## Input verification, identities and exact version gate

Accept a fixed sealed prefix and independently retained seal hash. First consume the entire decoder through `verification-complete` into a fresh staging directory; do not publish an index or any decision output from a failed prefix. Build a disk-backed, timestamp/sequence index and bounded per-episode input cursor from that verified spool, not an in-memory week of payloads. Preserve references to original journal entries, raw/gzip hashes, request/receipt/server clocks, all fleet/static/model fields and causal release states. Do not reconstruct inputs from sampled forecast rows. Original raw JSON remains authoritative; parsed payloads passed to the frontend retain original ordering and bus/row/distribution alignment.

A capture identity must be pinned independently of the prefix length. Define it from a canonical descriptor containing recorder commit/script hash, base URL, original manifest `startedAt` and the original sequence-zero journal-line hash; retain the descriptor and its SHA256. Receipt IDs become `(captureId, original sequence, bodySha256)`, release/gap IDs similarly retain capture ID and original sequence. Prefix seal hashes remain separate provenance, so extending a prefix neither changes earlier event IDs nor joins two different captures accidentally. A runner job accepts one capture lineage; combining unrelated captures is outside this plan.

The initial response is the first structurally complete, causally admissible fleet receipt in the closed raw-time interval `[scheduledAt, scheduledAt+30s]`. Empty service and missing/stale/invalid ETA remain eligible initial states. Never search beyond it for a supported version, usable ETA, better route or armable reminder. An earlier ambiguous fleet receipt in this search interval makes the initial state unknown, because it might have been the first usable response. A later complete response cannot clear that ambiguity.

For that exact initial receipt, require its linked `releaseStateId` and sequence, with `candidate_under_continuity_assumption`, safe clocks, unique eligible proof, complete observed HTML/module group and exactly the supported source/tree/file hashes and sizes. Check proof/bundle/health knowledge times against the original receipt. Apply policy `9ded9d0` explicitly and retain `strictIdentityKnown=false` and `assumptionRequired=true` in the episode manifest. Unknown/invalidation states cannot be omitted or replaced by an older supported mapping. Unknown source proof at the first complete receipt means version unavailable, not a search for another receipt.

A later valid same-build health response can restore a prior complete/proven bundle only from that recovery receipt, with its failure history retained. An observed different build requires a fresh complete matching group. After an episode binds a frontend, later build/resource/health uncertainty does not reload or stop that page by itself. Continue applying actually served feed/model inputs; retain those release observations separately. Unsafe capture clocks or ambiguous fleet inputs still stop causal interpretation as below.

## Clock conversion and event order

Retain the recorder's original UTC strings and monotonic durations in the spool. The JavaScript decision clock is explicitly integer epoch milliseconds: parse the original UTC date/time, pad a short fractional part to three digits or discard digits after its first three, then parse that normalized UTC string. For these positive epochs this is millisecond truncation, not rounding. Reject malformed/non-UTC/out-of-range values. Retain the original higher precision fields and the conversion rule in provenance. This may require adding original timestamp strings to compact decoder events; it must not change their original evidence values.

Initial-window eligibility, ordering, version proof availability and capture-horizon coverage use original timestamps/sequence, **before** conversion. A receipt at start+30.000001 seconds is outside the start window even if it maps to the same JavaScript millisecond as the boundary. Do not round `server_eta.at`, `servedAt`, per-bus observation times or model values. The actual attachment code computes forecast age from the injected `Date.now()` and served fields.

Use one actual component session per JavaScript process, with the pinned fake Date/timer implementation and `America/New_York`. The source has module-global route/model/anchor stores, so simultaneous episodes must use isolated processes, never share a session's stores. Reset stores and timers at episode boundaries and assert no leaked timers or offline-anchor entries.

Advance actual timers through every wall second, preserving fractional millisecond phase after the explicit conversion. At a feed time, execute all already-due timers first, settle component effects, then apply the receipt and settle effects. Equal converted feed times retain original journal order and each application settles before the next. Synthetic movement updates follow already-due timers at wall-second boundaries as in the existing adapter. Never batch a 45-minute timer jump that coalesces React updates. At a horizon tie, timers then any included receipt then the terminal snapshot run in that order. Only original-time receipts at or before the fixed horizon are included.

## Missing, failed, ambiguous and unfinished inputs

Keep independent initial-state, temporal-coverage and execution-status fields; they are not interchangeable denominators.

| Situation | Required handling |
| --- | --- |
| Full initial 30-second interval is covered, but no structurally complete receipt | `missing_initial_response`; preserve the episode key |
| Prefix ends before a complete initial search interval, with no selected initial receipt | `initial_window_uncovered`, not a proven missing response |
| Ambiguous fleet input before an initial response can be selected | `initial_input_unknown`; no later initial search |
| First complete response has unknown/unsupported version | `initial_version_unavailable`, with exact reason and receipt |
| Known HTTP/read/JSON/schema failure after initialization | Follow the actual parent poll failure path; never substitute an empty successful fleet |
| Recorded schedule gap | No invented poll; run existing timers against the last actual state and record skipped slots |
| Safe-clock ambiguous fleet receipt during an episode | Advance due timers to its converted receipt time under the frozen tie convention, retain the known prefix, then stop before applying that unknown response |
| Clock becomes unsafe | Stop at the last established safe journal/time boundary; never sort, repair, shift or resume using later clock-unsafe records |
| Known prefix ends before the horizon | Stop at the last safe observed coverage point, preserve the original 45-minute horizon, mark the remaining interval uncovered |
| Later health/build ambiguity after a page was bound | Retain it as version evidence; no page reload or automatic termination |

No ambiguous input is converted into `fail()`, empty fleet or a stale-data carry-forward that is then presented as a fully known decision path. Once an episode's input becomes unknown, do not resume it after a later recovery: intervening plan/reminder/walking state could have changed. Emit `knownThrough` with original sequence/time, first uncertainty reason and an unknown suffix through the scheduled horizon. Earlier pure signals and walking records remain descriptive prefix evidence, not physical pickup claims. For clock-unsafe records whose wall time cannot locate an event, use the last safe sequence/time as the conservative boundary and retain the original unsafe timestamp separately.

The terminal mutable manifest cannot extend coverage beyond the sealed journal. Retain terminal unpersisted-response and unjournaled-gap metadata as uncertainty; do not synthesize their unknown locations or polls. An unsupported version does not erase an independent unfinished horizon. Report full counts by date, profile and generating route: scheduled, initial eligible/missing/unknown/uncovered, version qualified/unavailable, temporally complete/truncated/unknown, execution success/resource failure, and assumption-qualified versus strict identity known (the latter remains zero). Include feed failures, gaps and model/ETA unavailability separately. Every scheduled profile remains in the reconciliation even if no component can be mounted.

## Streaming outputs and source parity work

Before scaled execution, remove two implementation limitations without changing production:

1. The present adapter retains `events[]`, and `runEpisode` buffers full snapshots. Add an optional bounded event sink and explicit backpressure/draining at already-settled action/wall-step boundaries. Keep the original buffered path only for bounded reference fixtures. Emit state updates, feed applications/failures, arm/signal/disarm/movement transitions, initial and terminal snapshots immediately. Do not retain cumulative prior events inside each new row or create a week-sized output array.
2. The parent sets `latestApplied` before applying payload fields; its guarded catch can differ from the adapter's generic catch when a structurally valid payload throws during application. Extract the actual poll control/application/catch block by AST, retaining original sequence/abort guards, and feed it an in-memory response boundary. Remove real fetch/anonymous-ID delivery through a research sink, not a rewritten decision rule. Test both pre-application failure and a payload that throws after `latestApplied` advances against that exact original block. The observer remains serial at captured receipt times; it does not claim the historical browser's five-second request/abort ordering.

Use append-only compressed JSONL with bounded writable buffering and backpressure. Include schema, capture/protocol/source IDs, scheduled episode ID and a per-episode event sequence in every stream. Full option/rank/visibility values remain available when their actual state updates; do not drop hidden options or reduce to top choice. Preserve semantic distinctions such as undefined and nonfinite diagnostic values with an explicit tagged serialization codec; never silently turn Infinity/NaN into JSON null. Original fleet wire bytes are referenced rather than redundantly embedded in every decision row.

Write a terminal per-episode manifest with row counts, byte counts, content/compressed hashes, first/last known times, uncertainty and status. Publish a shard completion marker only after every assigned key is reconciled and its output closes successfully. A late integrity or write failure invalidates the affected run/shard, not a silently shortened stream. Keep resource failures explicit; do not retry a different geometry/start/profile as a replacement.

# Execution partition amendment — pinned before the full benchmark

September 22, 2026. Root approved this execution-only amendment after synthetic pilot **35737549231** completed all 84 profiles. The pilot worker took 163.79 seconds and input generation took 6.41 seconds. Repeating generation in each original seven-day route job would put its projected duration too close to the approved limit. The pilot also exposed unequal output volume across geometry strata. These are synthetic workload/resource observations, not arrival scores or reasons to change any scenario.

The full benchmark is now **98 fixed route/date shards**: the same 14 generating routes × the same seven dates, each with exactly **3 geometries × 48 starts × 2 profiles = 288 profiles**. The total remains **28,224**, with unchanged O/D bytes, start times, 45-minute horizons, A/B behavior, baseline component, source proof, input/uncertainty rules and 168 predetermined retained full streams. This supersedes only the original plan's 14 jobs containing seven daily workers.

Generate each complete synthetic daily input **once**, then reuse its hash-identical verified spool across all 14 routes for that date. Daily generation uses the committed global poll index, so overlapping adjacent-day inputs must agree on raw fleet-body hashes at the same original receipt time. Preserve original sealed-prefix identity, readiness/database hashes, raw body hashes, original timestamp metadata, generator/source hashes and generation resource reports with each shared artifact. Independently check overlapping daily metadata before claiming full benchmark completion. No joining of actual captures or retrospective source attribution is introduced.

The workflow has separate phases: one baseline-asset preparation; seven date-generation jobs; 98 route/date workers; final reconciliation. Generation jobs finish before worker jobs begin. Both matrices have maximum parallelism **four**, so the combined benchmark never exceeds four concurrent generation/worker jobs. Each worker process executes its assigned 288 profiles sequentially, with fresh component/timer state for each. There are no concurrent React globals.

Limits remain **2 GiB aggregate RSS**, **8 GiB scratch** and **at most 90 minutes per job**. Both generation and workers use the same descendant/process-group resource watchdog. Worker-owned temporary directories are placed inside the monitored checkout. Keep a five-minute finalization reserve. Record generation cost once per date, worker cost once per shard, and setup/job timing separately; do not omit generation or multiply its cost by the number of artifact consumers.

Write each shard's exact expected keys before dependency/download/execution steps. Reconcile failures and missing artifacts against all 98 fixed assignments, retaining every key and uncertainty/status reason. A failed generation artifact cannot silently remove its date's 4,032 profiles. The final benchmark succeeds only when all 28,224 keys have the expected completed baseline execution and all seven shared inputs satisfy their provenance/overlap checks.

Before launch, run affected partition, shared-input and failure-reconciliation fixtures on hosted runners. No new user confirmation is required when these gates pass; root explicitly authorized this amendment. The existing successful pilot remains the pilot for the unchanged component/workload. No prospective body, actual future outcome, candidate arm or physical pickup label is opened or changed.

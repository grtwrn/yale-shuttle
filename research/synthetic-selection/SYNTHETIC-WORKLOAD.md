# Fixed synthetic workload and execution envelope

This generator/runner is committed before the pilot and full benchmark. It reads only the two frozen static JSON files and reproduced baseline frontend assets. Its dates label the approved synthetic schedule; they are not observed September 23–29 outcomes. The exact pinned recorder is driven through an in-memory HTTP opener, with no public/private network delivery.

`make_synthetic_capture.py` pins the arithmetic workload: two buses per each of 14 canonical routes; route phase `(globalTick // 4 + busOrdinal * 7) % routeLength`; 15-second ticks measured from September 23 04:00Z; original canonical stop order, coordinates and published paths; two full future occurrence cycles; point `30 + 15 * ((globalTick + busOrdinal) % 3) + 90 * (hop - 1)` seconds; low=max(0,point−30), high=point+60; departure=max(0,point−20), floor=max(0,low−20); 50 monotone integer points spanning low/high. Segments are fixed avg=90, sd=15, n=100; dwells avg=20, sd=5, n=100. No value is fitted. All supplied routes face the original service filter. Global tick, rather than capture-local tick, makes overlapping daily synthetic captures agree on fleet bytes at the same absolute poll time.

The first health/HTML/module observation occurs 60 seconds before each synthetic block's start, and every required asset must match the already pinned source proof. Poll requests begin 700,000 microseconds after each slot, with one synthetic microsecond per HTTP response; health precedes the fleet on every fourth slot. Serve/forecast clocks stay at the slot's integer millisecond request value. The initial proof still has its actual September 22 06:01:55Z knowledge time. No synthetic source mapping is invented for other bytes.

Integration alone uses a 60-second capture and adds an inert, explicitly synthetic field to the third response to produce exactly **7.5 MiB raw JSON**. This verifies the legal-body boundary without changing any ETA field. The pilot uses 45 minutes of input plus its final receipt. Full daily blocks use 24 hours 15 minutes plus the final receipt, retaining required adjacent context. These response bytes do not assert actual motion, physical arrivals or boardability.

The hosted integration already exercises exact asset proof → actual recorder → sealed prefix → verified SQLite spool → actual component for A/B. The full benchmark uses the same path for every scheduled profile. Workers stream option/state updates through bounded gzip output and retain per-episode terminal manifests; they never retain cumulative full-week decision arrays. SQLite cursor rows and one body are read at a time. Only the fixed daily block of small terminal summaries is accumulated.

The benchmark watchdog samples **aggregate RSS of the coordinator, worker process group and every descendant** every 0.1 seconds, and allocated scratch bytes across the whole checkout every two seconds (deduplicating hard links). It kills the workload on a measured cap violation and reports the measured peak and limit. These are sampled measurements, not a claim of an instantaneous hardware-enforced RSS bound. Tests deliberately launch two toy allocation children to ensure their aggregate, not just the coordinator, triggers enforcement. No React sessions run concurrently inside a worker. Daily workers exit before the next begins.

The 2 GiB RSS / 8 GiB scratch / 90-minute job limits and four-job parallel maximum are unchanged. The coordinator reserves the final five minutes for reconciliation/upload by stopping its child workload earlier. Every job writes all assigned keys before dependency/build/execution steps. Failure reconciliation emits an explicit status for each missing key; the final cross-job reconciler also reconstructs missing artifact keys from the frozen schedule. A pilot pass cannot satisfy the full 28,224-profile denominator.

Synthetic full-benchmark streams may be removed only after successful close, hashes and terminal manifest persistence. Full streams retained in the full benchmark are the first and last scheduled start for every scenario/profile: exactly 168 predetermined streams. All byte/row totals include removed synthetic performance streams. The pilot retains all 84, and integration retains both. This deletion policy does not authorize removing actual prospective captures or outputs.

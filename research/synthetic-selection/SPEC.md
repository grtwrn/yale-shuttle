## Exact extraction and execution boundary

Use the TypeScript parser to select original AST nodes and preserve their complete source text, including hook dependency arrays. Generate research modules on the hosted runner; do not maintain a hand-copied live update function. Every extracted range receives a source position, selector and SHA256 in a generated manifest.

The adapter retains the original endpoint/time states, reminder states/refs, stableOptions memo, empty-plan roster refresh effect, live options memo, option/context refs, reminder effect, ranking refs/memo and visible-option refs/memo. Dependencies use actual imported planner, arrivals, pickup selection, journey arrival, ranking, ETA attachment, service filtering and reminder exports. Extract the parent poll's successful application statements to preserve conditional field updates, parameter/path registration, filtering, attachment to the exact bus array, failure flags and receipt clock. A failed transport keeps the previous fleet and sets failure; it is not an empty feed.

React itself runs the extracted hooks/effects, with a deterministic synthetic clock and controlled timers. One-second parent renders are required: `etaFresh` is evaluated each render and may invalidate options at source expiry. They must not force the live memo or plan to recompute while dependencies are unchanged. An empty-plan roster/freshness change may cause an effect-driven refresh and second render. Preserve identity of unchanged inputs between renders; a newly received JSON body is a new input. Ranking's 30-second pending period advances only on its real dependencies.

The reference executes the complete original TripPlanner function body in React, instrumented to expose state/actions and replace its final rendered UI with a null render boundary. All original pre-return statements and effects remain. This is component-state parity, not DOM/layout or browser scheduling parity. No Leaflet tree is mounted. Module boundary mocks disable weather/network, storage/recents, logging, permissions and delivery; those mocks cannot replace a decision export. The adapter and reference run independently, with fresh module state/timers, and compare full decision snapshots after each settled event. Unexpected external I/O fails fixtures.

Extract the actual reminder button condition and onClick handler for the synthetic arm boundary. The UI requires `walkToSec >= 60` and valid leaveInput. A short-walk initial choice is recorded as ineligible, remains at its actual origin and never receives a fabricated arm/ping. The actual reminder effect checks immediately on arm, uses latest refs thereafter, permanently disarms on null input, marks heads-up without walking, and disarms on leave-now. The research delivery stub records the pure ping/message; it cannot deliver a notification. Profile B begins walking only on leave-now.

## State/output contract and fixed policies

Keep full stable, live, ordered and visible option arrays (including all occurrence/distribution fields); roster/refresh identity; ranking order/tier/pending/since; kept-third identity; armed route/board/alight; fired flags; selected/countdown/boardable identities; feed application/failure/age and actual receipt clocks; all pure signals and action reasons. Record transitions even when no signal occurs. Expose diagnostic desired order through the actual ranking export without mutating rank state. Do not join predictions_log or insert outcome-selected options.

Use the 42 O/D manifest and protocol policy verbatim. Initial choice occurs once after initial React effects settle. Profile A never arms or moves. Profile B attempts only the first ordered choice: direct walk starts immediately, eligible shuttle arms once, ineligible choice never retries. Frozen origin and destination remain planning inputs; injected live location changes only remaining walk. Walk interpolates frozen endpoints at distance/1.1 m/s, updates on wall seconds, clamps at endpoint, and never fabricates boarding. Changed/missing board geometry is unresolved. End-of-horizon, missing start response, unsupported source, missing/invalid/stale ETA, failed response and timer/feed ties remain explicit. For ties at an identical millisecond, advance already-due frontend timers first, then apply receipt, then settle React, and record this deterministic observer convention; it is not a claim about historical browser event-loop ordering.

## Hosted parity gate, before any replay inputs

Fixtures contain synthetic complete public response objects derived from existing pre-September-21 static source/geometry. No outcomes are needed. Compare original full component versus extracted adapter across each complete event sequence, not just exported functions in isolation. Assert independently expected behaviors as well as parity so shared bugs/empty fixtures cannot pass vacuously.

Required cases: initial all-option planning; normal poll preserves route/stop-pair and initial bus pin; roster appearance refreshes shuttle-less plans; live location changes remaining walk without refreshing plan; countdown versus another boardable bus; same bus later occurrence; raw at-stop gate; invalid/missing/stale ETA and failed transport; permanent disarm with no recovery rearm; selected vehicle disappearance; heads-up then leave-now once; short-walk no arm/no movement; rank change held for 30 seconds; kept-third visibility hysteresis/reset; independently recorded desired versus displayed order; source/hash selector failure. Full response age must be allowed to expire between successful polls.

A second layer verifies profile policy/walking around that component contract. No replay of future recordings is part of this implementation gate. Report missing lifecycle coverage or unsupported event ordering before claiming the adapter ready. Keep candidate and outcome adapters unimplemented.

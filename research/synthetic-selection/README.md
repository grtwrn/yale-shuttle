# Synthetic selection baseline adapter

Research-only component-state implementation of the corrected prospective protocol at [`6dfbe4f`](https://github.com/grtwrn/yale-shuttle/blob/6dfbe4f/research/phase-encounters/PROSPECTIVE-SELECTION-PROTOCOL.md). Source/extraction/parity rules were committed first at `e3ab99a`; see [SPEC.md](SPEC.md). The [supported source/bundle mapping](VERSION.md) is exact for deployed `05a9881` only.

`extract.mjs` uses TypeScript AST nodes from the unchanged production source. It emits an adapter, a reference containing the entire original TripPlanner body before its final JSX return, the parent poll's successful application block, and the parent's aligned wall-second timer. All source ranges and generated bytes are hashed. Missing/ambiguous selectors, a changed TransitMap hash, a changed frontend tree or tracked frontend edits fail closed. The original planner/ranking/reminder/arrival exports are imported directly.

`adapter.ts` mounts either component in the real pinned React reconciler with a caller-controlled global clock. The two components settle independently across the same synthetic input sequence. Original hook dependencies, automatic roster refresh, frozen plan pins, live boarding selection, ranking, visibility and immediate/interval reminder effects run unchanged. The original button condition/onClick provides the synthetic arming boundary. Delivery, storage and logging are research sinks. A populated offline anchor store fails the run rather than silently substituting a retrospective estimator.

`envelope.ts::runEpisode` accepts already-verified public receipt envelopes, a synthetic O/D, scheduled start and causal release metadata. It selects the first complete response in 30 seconds, preserves invalid or missing ETA as an initial state, binds the supported frontend once, applies failures separately from empty fleets, and ends at scheduled start plus 45 minutes. It records missing starts, unsupported/ambiguous versions and unfinished capture horizons. Complete response structure requires buses plus routes, stop names/coordinates, segments and dwells; ETA validity is deliberately separate. Changed server builds remain input metadata without changing the bound frontend.

The session records complete stable/live/ordered/visible option arrays, rank and kept-third state, selection-update times, initial choice, arm eligibility/rejection reason, actual pure ping kind/message/fired flags, permanent disarm, walking start/path and unresolved board geometry. Profile B never changes its initial choice, retries an arm, walks on heads-up, teleports a short-walk origin, or infers boarding. Motion updates occur on wall seconds, after already-due timers; a fractional leave time remains the exact walking start time. At equal receipt/timer times, timers run first, as frozen in the spec. This is an observer convention, not evidence about historical browser ordering.

Execution is hosted only through `.github/workflows/synthetic-selection.yml`. It installs the unchanged app locks and `react-test-renderer@19.2.6`, generates extracts, runs synthetic component/envelope fixtures and verifies production source is unchanged. No prospective capture is opened by that workflow. Fixtures use synthetic complete public response objects and pre-September-21 static stop coordinates, including all source route labels and the existing service gate/cap.

The remaining boundary before any real prospective replay is explicit: verify/decode the capture journal and immutable body hashes, derive causal release availability from its metadata, enumerate the separately pinned 42 scenarios, and provide a bounded streaming clock/runner for all 28,224 profile episodes. `runEpisode` currently buffers diagnostic rows for its bounded fixtures; it is not a scale-tested whole-week runner. No capture decoder, candidate arm, fitting, arrival-error scorer or physical boarding/outcome adapter is implemented here.

Parity is for component state with the final rendered UI replaced by a null boundary. It does not establish DOM/layout, browser scheduling/background throttling, delivery permissions or real rider behavior. The public feed's 15-second cadence is the synthetic observer's information limit. The source's six-shuttle planner cap is preserved; internal pre-cap candidate pairs are not exported. This work supplies no evidence clearing the 32 earlier physical pickup barriers, the other encounter censors, or validating the 643 Blue additions. Brown September 23–29 and every other prospective outcome remain unopened.
